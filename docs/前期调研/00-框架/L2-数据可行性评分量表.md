# L2 数据可行性 · 评分量表

**性质**：Claude Code 独家制定 —— 把判断标准显式化，使 Codex 能机械化应用
**日期**：2026-10-15

---

## 一、为什么要有量表

L2 是整个调研的**关键筛选闸**（正大杯是市场调查赛事，无数据即无调查）。若只写"评估数据是否可得"，评估会因人而异、无法复核。

**把判断标准写成可打分的量表**，带来三个好处：
1. **可复核**：每个方向的得分有据可查，我能低成本审核 Codex 的结论；
2. **可比较**：不同方向的得分直接并置，方向簇的取舍有客观依据；
3. **可复用**：这是选题无关的通用工具，任何方向都能套用。

---

## 二、七个维度（满分 100）

| 维度 | 分值 | 评分要点 |
|---|---|---|
| **D1 合法性** | 20 | 数据获取是否合法合规？个人信息？平台规则？法条依据是否明确？**存在实质法律风险的直接判 0，一票否决。** |
| **D2 可获得性** | 20 | 实际拿得到吗？是否需要付费、申请、内部关系？公开渠道能否覆盖？ |
| **D3 颗粒度** | 15 | 数据粒度是否支撑既定研究问题？只有宏观汇总数据做不了微观行为分析。 |
| **D4 时效性** | 10 | 数据是否足够新？赛程内能否拿到最新一期？ |
| **D5 规模充足性** | 15 | 样本量/记录数是否足以支撑统计推断？有无抽样偏差的结构性问题？ |
| **D6 成本** | 10 | 时间成本与金钱成本。赛程时间窗内是否可行？ |
| **D7 可验证性** | 10 | 数据能否被交叉验证？单一来源、无法核实的风险有多大？ |

---

## 三、判定阈值

| 总分 | 判定 | 处置 |
|---|---|---|
| **≥ 75** | ✅ 可行 | 进入 L3/L4 |
| **60 – 74** | ⚠️ 存疑 | 进入方向簇，但标注为主要风险 |
| **< 60** | ❌ 不可行 | 淘汰，除非能找到替代数据源翻盘 |

**一票否决项（无论总分）**：
- D1 合法性存在实质法律风险的
- 依赖"内部数据 / 假设数据 / 编造数据"才能成立的

## 四、评分的操作规范

**每个方向必须产出如下表格**：

| 维度 | 得分 | 依据（含来源编号与证据强度） |
|---|---|---|
| D1 合法性 | /20 | |
| D2 可获得性 | /20 | |
| D3 颗粒度 | /15 | |
| D4 时效性 | /10 | |
| D5 规模充足性 | /15 | |
| D6 成本 | /10 | |
| D7 可验证性 | /10 | |
| **合计** | **/100** | |

**硬性要求**：
- 每一项得分**必须附依据与来源**，来源指向 `DEPLOY-002` 的渠道手册或专项调研材料。
- **不能只给分不给依据**。若某维度信息不足，写"信息不足，暂记 0 分并标注为待补"，不得臆测。
- 证据强度为<span class="ev ev-w">弱</span>的依据，只能支撑不超过该维度 50% 的分数。

## 五、与其他层的接口

- **输入**：L1 输出的痛点池（每条痛点对应一个待评估的数据需求）
- **调用的工具**：`DEPLOY-002` 产出的《通用数据来源与合规边界》手册
- **输出**：每个方向的 D1–D7 评分表 + 总分 + 判定，供 L5 方向簇取舍

**专项数据调研**（针对具体方向去查该方向独有的数据源）为后续任务，本次量表先用于**通用可行性判定**。

---

## 六、我认为最可能出问题的两处（提醒审核时重点看）

1. **D5 规模充足性容易被高估**。Codex 可能拿"平台上有海量内容"当作数据充足，但**平台数据不代表总体**（这是典型的可得性偏差），评分时应重点质疑。
2. **D2 可获得性容易与 D1 混同**。"技术上拿得到"不等于"合法拿得到"，两维必须独立评分。
